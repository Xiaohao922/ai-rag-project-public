## 1. 需求背景

### 1.1 问题定义

风控领域知识问答的核心矛盾是：**知识存在，但不可及**。

业务规则、指标口径、处置流程散落在多份文档里，从业者提问时依赖人工检索和资深同事答疑。知识本身不缺，缺的是一个统一、可对话、可溯源的获取入口。

### 1.2 现状痛点

| 痛点 | 说明 |
|---|---|
| 知识分散 | 跨文档检索难，同一个概念多个出处、多个口径 |
| 口径不一致 | 业务指标、处置流程缺乏统一问答入口 |
| 答疑依赖人 | 新人上手依赖资深同事，知识没有沉淀为可复用服务 |

### 1.3 为什么现在做

大模型 + RAG + 微调技术栈已成熟，可低成本复现"从需求定义到安全评测"的完整 AI 产品链路。本项目既解决领域知识问答的实际问题，也验证 AI 产品从应用层到模型层到安全验证的方法。

## 3. 产品概述

### 3.1 一句话描述

构建一个**风控 & AI 领域专业知识问答助手**（垂直问答，非通用聊天），基于知识库回答专业问题，超范围问题明确拒答，回答带引用溯源。

### 3.2 产品价值

| 维度 | 价值 |
|---|---|
| 知识可对话 | 把散落文档变成可自然语言查询的问答服务，降低检索成本 |
| 答案可溯源 | 回答展示知识库来源，支持核对，减少口径混乱 |
| 边界可防御 | 超纲问题明确拒答，对注入/越狱等攻击有防护 |
| 方法论 | 沉淀可复用的 RAG 搭建、检索调优、模型微调、安全评测方法 |

### 3.3 产品链路

```
用户输入 → 查询改写（多轮上下文补全）→ 知识检索（混合检索 + 重排序）
         → 回答生成（带引用）→ 输出
```

### 3.4 MVP 最小切口

**MVP 范围**：单轮专业问答 + 边界拒答 + 引用溯源 + 基础安全防护（Prompt 注入防御）。

**MVP 后迭代增强**：多轮指代消解、查询改写、模型微调对齐、进阶安全评测。

## 7. 风险与能力边界

### 7.1 能力边界（重要）

- **知识边界**：RAG 无法覆盖训练数据外的知识（如企业内部 RAP/KAP 口径），必须靠数据或检索供给，不能靠模型凭空产生。
- **能力边界**：检索层无法判断知识点是否存在，超纲问题需 Prompt 层拒答兜底。
- **安全边界**：对齐训练可强化拒答行为，但不能注入未覆盖知识。

### 7.2 风险与依赖

| 风险 | 影响 | 缓解 |
|---|---|---|
| 知识库覆盖度不足 | 回答准确率受限 | 扩充数据 / 依赖 RAG |
| API Token 额度有限 | 大批量测试受阻 | 分批执行 |
| 知识库存储上限 | 无法新增文档 | 控制分片策略 |
| 回填式 PRD | 验收标准来自实践回填，非做前定义 | 明确标注，保留实践依据 |
