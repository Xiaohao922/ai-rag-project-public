## 2. 项目阶段与产出

### 2.1 项目一：RAG 问答助手（✅ 已完成）

**目标**：搭建风控 & AI 领域专业知识库 RAG 问答助手，覆盖数据准备、分片策略、检索调优、评测、上线全流程。

**核心动作**：
- 知识源：10 份 PDF（风控业务、RAG 工程、AI 评测）
- 分片策略：Parent-Child 父子分片（父块 800 字符/重叠 150，子块 200 字符）
- 检索：text-embedding-v4 向量化 + qwen3-rerank 重排序 + 混合检索
- 对话生成：DeepSeek，强约束 Prompt（仅基于知识库作答，无依据拒答，展示引用）

**关键结果**：
- 15 条用例基线召回测试：通过 10 条，准确率 66.7%
- 定位问题：纯向量检索在专有名词、同义改写场景下 Top1 命中率不足
- 优化：切换混合检索后关键失败用例召回明显改善

**踩坑记录**：
| 问题 | 根因 | 解决 |
|---|---|---|
| PDF 切片产生大量 1-20 字符碎块 | PDF 硬换行符 | 切换 Parent-Child 父子分片 |
| 向量存储翻倍接近上限 | 父子分片双套索引 | 控制文档规模 |
| 同义改写召回差 | 纯向量对表述差异敏感 | 混合检索补充关键词匹配 |
| 超纲问题不返回空 | 检索层无法判断知识点是否存在 | Prompt 层拒答兜底 |

### 2.2 项目二：查询改写 RAG（✅ 已完成）

**目标**：在项目一基础上新增查询改写链路，解决同义表达、多轮指代导致的检索输入质量问题。

**核心动作**：
- Dify Chatflow：用户输入 → 查询改写 → 知识检索 → 回答生成 → 回复
- 查询改写结合会话上下文补全指代、规范术语、生成独立检索问题

**关键结果**：
- 多轮指代消解验证通过（"这些指标"→ 可独立检索的问题）
- 知识库未覆盖问题保持拒答，符合设计预期

**核心结论**：查询改写改善检索输入质量，但不能弥补知识库知识缺口；证据不足时拒答优于强行回答。

### 2.3 项目三：SFT 微调（✅ 已完成）

**目标**：在开源小模型上做领域微调，体验数据构造、训练、评测全流程。

**核心动作**：
- 基座：Qwen2.5-1.5B-Instruct-4bit（MLX 量化版）
- 训练：LoRA/SFT，200 steps，学习率 1e-5，batch size 1
- 训练集 64 条 + 验证集 16 条 + 独立测试集 20 条（零重复）

**关键结果**：
- 角色边界和拒答行为明显改善
- 300 steps 明显过拟合（train loss 降、validation loss 升）
- RAP/KAP 定义全档失败（训练数据未覆盖）

**核心结论**：
1. SFT 能稳定塑造角色/拒答行为；
2. SFT 不能注入训练数据之外的知识；
3. 训练越久不等于效果越好（200 steps 为实验候选）。

### 2.4 项目四：DPO 对齐（✅ 已完成）

**目标**：在 SFT 模型基础上做偏好对齐，理解 RLHF/DPO 流程与权衡。

**核心动作**：
- 偏好数据：39 对（35 训练 + 4 验证）+ 12 条边界样本
- 路线修正：先在 HF 基座直接 DPO 失败 → 修正为"先 SFT 再 DPO"
- DPO：30 steps，学习率 5e-6，LoRA r=8

**关键结果**：
- DPO-on-SFT：角色/拒答/蓝军口径达标
- 基座直接 DPO：角色全面退化（失败记录已归档）

**核心结论**：
1. DPO 必须在 SFT 基础上做；
2. DPO 强化行为，不注入知识；
3. 对齐训练不必然付对齐税（加正常对照组验证）。

### 2.5 项目五：综合评测（✅ 已完成）

**目标**：对完整搭建 + 训练的对齐模型做系统评测，验证安全边界。

**核心动作**：
- 功能评测 20 条（风控/RAG/AI 工程/边界）
- 安全评测 18 条（注入/越狱/敏感/多轮诱导/输出安全）
- 三条实验链纵向对比：DPO-30 基座 vs HF-SFT-v4 vs DPO-on-SFT-30

**关键结果**：

| 指标 | 数值 |
|---|---|
| 功能准确率 | 75%（15/20） |
| 边界拒答 | 100%（3/3） |
| 安全防御率 | 94.4%（17/18） |
| 越狱防御 | 100%（4/4） |
| Prompt 注入 | 75%（3/4，1 部分通过） |
| 多轮诱导 | 100%（3/3） |
| 输出泄露防御 | 100%（2/2） |
| 对齐税 | 0%（无过度拒答） |
| 综合评分 | 87.6 分 |

**关键失败案例**：
- RAP/KAP 定义错误：训练数据无可靠定义，三代模型均编造
- 混合检索与多模态检索概念混淆（部分通过）

## 3. 技术架构与关键参数（最终锁定）

| 层 | 选型 | 参数 |
|---|---|---|
| 基座模型 | Qwen2.5-1.5B-Instruct | LoRA r=8, alpha=16 |
| 分片 | Parent-Child 父子分片 | 父块 800/重叠 150，子块 200 |
| Embedding | text-embedding-v4（通义） | 高质量向量索引 |
| Rerank | qwen3-rerank（通义） | |
| 检索模式 | 混合检索（向量 + 关键词） | Top-K=6，无相似度阈值 |
| 查询改写 | deepseek-v4-flash | Chatflow 节点 |
| 对话生成 | DeepSeek | 强约束 Prompt |
| SFT | MLX + mlx-lm | 200 steps, lr 1e-5 |
| DPO | Transformers + TRL/PEFT | 30 steps, lr 5e-6, beta 0.1 |

## 4. 核心洞察

1. **知识靠数据供给，行为靠训练塑造**：SFT/DPO 改变不了训练数据没覆盖的知识（RAP 三代都答不对）
2. **DPO 必须在 SFT 基础上做**：直接在基座做 DPO 角色全面退化，必须 SFT → DPO
3. **RAG 的"知道不知道"分层解决**：检索层不识别超纲，需 Prompt 层拒答兜底
4. **对齐训练不必然付对齐税**：加了正常对照组验证，无过度拒答
5. **调优必须基于实测**：混合检索、Top-K 参数均通过对照实验确定，不凭经验拍板

## 5. 已知限制与后续规划

### 已知限制
- RAP/KAP 等企业知识训练数据未覆盖，无法靠训练注入；
- 测试集规模（38 条）适合项目实践，非生产级结论；
- 未覆盖多模态攻击、Agent 工具滥用等高级安全场景；
- 未做全量 15 条线上回归（token 预算控制，仅跑重点失败用例）。

### 后续规划
1. 扩充领域训练数据，补齐 RAP/KAP 等关键概念；
2. 扩大偏好数据规模（39 → 数百对）；
3. 扩展测试集（38 → 百级）；
4. 针对格式注入加"禁止回显用户指令"防护并回归；
5. 补充多模态、Agent 场景安全评测。
