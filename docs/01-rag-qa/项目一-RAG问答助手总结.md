## 三、完整过程记录

### 3.1 需求定义
- 目标：搭建风控领域专业知识库 RAG 问答助手，模拟企业 AI 产品从需求到上线的完整流程
- 为什么选风控领域：安全风控方向的行业知识积累，与专业领域对口
- 为什么选 Dify：快速验证，聚焦产品逻辑而非工程搭建

### 3.2 数据准备 & 踩坑
- 原始材料：10 份 PDF，覆盖风控业务知识、RAG 工程实践、AI 评测体系
- **踩坑 1：PDF 硬换行 → 通用切片产生大量 1-20 字符残缺碎块**
  - 根因：PDF 内部存在大量硬换行符，通用切片模式按换行断句，导致语义碎片化
  - 解决：切换为 Parent-Child 父子分片模式，子块 200 字符精确定位，父块 800 字符提供上下文
- **踩坑 2：Parent-Child 双倍存储 → 接近 50MB 上限**
  - 根因：父子分片各建一套向量索引，存储翻倍
  - 影响：后续无法随意新增文档或新建同类型知识库，需精简数据或切换分片模式

### 3.3 基线召回测试
- 测试配置：Top-K=6，纯向量检索，无相似度阈值，Rerank 开启
- 用例设计：15 条，分 4 类场景
  - 精准知识点（7 条）：直接匹配原文表述
  - 同义改写（3 条）：换一种说法问同样知识点
  - 专有名词（4 条）：术语定义查询
  - 超纲边界（1 条）：知识库不覆盖的问题
- 基线结果：

| 场景 | 通过数 | 总数 | 准确率 |
|------|------:|------:|------:|
| 精准知识点 | 5 | 7 | 71.4% |
| 同义改写 | 1 | 3 | 33.3% |
| 专有名词 | 4 | 4 | 100% |
| 超纲边界 | 0 | 1 | 0% |
| **合计** | **10** | **15** | **66.7%** |

- 失败用例根因：
  - RAG-004 / RAG-006：主题命中但知识点未命中，目标片段未进入 Top1 候选
  - RISK-002：细分知识点粗召回阶段未捞到
  - RISK-004：同义表述失配，向量相似度不足以排到前排
  - RAG-010：超纲问题，检索不返回空，返回主题相关通用片段
- 关键结论：**失败不是排序问题（Rerank 没问题），是粗召回阶段没有将目标片段捞入候选集**。仅调 Rerank 权重无法根治。

### 3.4 检索优化
- 方案：将检索模式从「纯向量检索」切换为「混合检索」（向量 + 全文关键词）
- 参数保持：Top-K=6，qwen3-rerank，不设相似度阈值
- 优化原因：纯向量检索对精确专有名词、同义改写场景召回弱，混合检索补充关键词匹配能力
- 回归结果：针对 5 条历史失败用例重点回归，召回表现明显改善
- 存储影响：混合检索是检索策略变化，不额外占用向量存储

### 3.5 对话助手搭建 & 发布
- 应用类型：Dify 对话助手
- 系统 Prompt：强约束规则——仅基于知识库作答，无依据则固定话术拒答，展示引用来源
- 冒烟测试：基础问答、超纲拒答均通过
- 已发布线上版本

### 3.6 最终锁定配置

| 参数 | 值 |
|------|------|
| 分片模式 | Parent-Child 父子分片 |
| Embedding | text-embedding-v4 |
| Rerank | qwen3-rerank |
| 检索模式 | 混合检索 |
| Top-K | 6 |
| 相似度阈值 | 未设置 |
| 生成模型 | DeepSeek |
| Prompt 约束 | 仅基于知识库作答 + 无依据拒答 + 展示引用来源 |

## 四、工程踩坑总结

| 编号 | 问题 | 根因 | 解法 | 通用教训 |
|------|------|------|------|------|
| 1 | PDF 切片大量碎块 | PDF 硬换行符 | Parent-Child 父子分片 | 数据预处理是 RAG 质量的前提，不能假设输入干净 |
| 2 | 存储翻倍接近上限 | 父子分片各建一套索引 | 控制文档规模，后续精简数据 | 选型要评估资源约束，不是效果越好越合适 |
| 3 | 同义改写召回差 | 纯向量检索对表述差异敏感 | 混合检索补充关键词匹配 | 没有一种检索方式万能，组合检索是工程常态 |
| 4 | 超纲问题不返回空 | 检索层无法判断知识点是否存在 | Prompt 层拒答兜底 | RAG 的"知道不知道"是分层解决的，不能只靠检索 |

## 五、项目价值总结

### 项目概述（一段话）

> **风控 & AI 专业知识库 RAG 问答助手**（AI 产品经理实践项目）
> 基于 Dify 平台从 0 到 1 搭建风控领域专业知识库 RAG 问答助手，覆盖数据准备、分片策略选型、检索调优、评测测试到上线发布全流程。采用 Parent-Child 父子分片模式，使用通义 text-embedding-v4 向量化 + qwen3-rerank 重排序；通过 15 条用例基线召回测试定位纯向量检索在专有名词和同义改写场景下 Top1 命中率不足问题（基线准确率 66.7%），将检索模式从纯向量升级为混合检索后召回表现明显改善。产出完整召回测试报告与优化前后指标对比，沉淀 PDF 硬换行致切片碎块、Parent-Child 存储翻倍等工程踩坑经验。

### 过程讲述框架（3 分钟版）

1. **背景**：模拟企业 AI 产品从需求到上线的完整流程，领域选择基于安全风控方向的行业积累
2. **方案**：Dify + 通义 Embedding/Rerank + DeepSeek，10 份 PDF，Parent-Child 分片
3. **踩坑**：PDF 碎块 → 切分片模式；存储翻倍 → 控规模；纯向量 67% → 混合检索改善
4. **评测**：15 条用例 4 类场景，基线 10/15，优化后关键失败用例回归通过
5. **收获**：RAG 能力边界（检索不识别超纲，需 Prompt 兜底）、参数调优必须实测、资源约束下的优先级取舍
