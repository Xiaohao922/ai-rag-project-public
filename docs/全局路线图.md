# AI 产品经理实战项目 全局路线图

> 更新日期：2026-08-26
> 目标：形成覆盖 RAG → 提示词 → 微调 → 强化训练 → 安全评测的完整 AI 产品能力线，项目叙事连贯，讲述有深度

---

## 设计逻辑

不是 6 个零散小项目，而是一条**从应用层到模型层递进、最终做安全验证的能力线**：

```
应用层（不动模型）              →  模型层（动模型）          →  安全验证
RAG + Prompt Engineering        →  SFT 微调  →  RLHF/DPO     →  AI 安全评测
```

项目叙事主线：**"我从应用层做到模型层，最后对完整系统做安全评测，每一步都不是纸上谈兵，有实测数据和踩坑记录。"**

## 项目二：Prompt Engineering & 查询改写 RAG（✅ 已完成）

| 维度 | 内容 |
|------|------|
| 覆盖能力 | Prompt 设计、多轮对话管理、查询改写/指代消解、Chatflow 工作流编排 |

## 项目三：SFT 微调实践（✅ 已完成）

| 维度 | 内容 |
|------|------|
| 覆盖能力 | 微调数据构造、SFT 训练流程、效果评测、模型能力边界认知 |
| 目标 | 对开源小模型做领域微调，体验从数据准备到训练到评测的全流程 |
| 关键动作 | ① 构造风控领域指令微调数据集（80 条训练）；② 在 Qwen2.5-1.5B 上做 SFT；③ 用测试集评测微调前后对比；④ 分析过拟合/知识注入效果 |
| 平台 | MacBook Pro（Apple M4 Pro / 24GB / MLX 框架） |
| 核心结论 | SFT 能稳定塑造角色/拒答行为；不能注入训练数据之外的知识（RAP/KAP 全档失败）；300 steps 明显过拟合，推荐 200 steps |
| 叙事要点 | "不是只会调 API，实际做过微调，知道数据构造、训练成本、效果评测、过拟合的坑" |

## 项目四：RLHF / 强化训练实践（✅ 已完成）

| 维度 | 内容 |
|------|------|
| 覆盖能力 | 偏好数据构造、DPO 训练、对齐效果评测、对齐税分析 |
| 目标 | 在 SFT 模型基础上做对齐训练，理解 RLHF/DPO 的流程和权衡 |
| 关键动作 | ① 构造 39 对偏好数据；② 直接 DPO 失败 → 修正为"先 SFT 再 DPO"；③ 评测对齐前后回答质量变化；④ 分析 DPO 强化行为、不注入知识 |
| 平台 | 与项目三共用 MacBook（Transformers + TRL/PEFT） |
| 核心结论 | DPO 必须在 SFT 基础上做（基座直接 DPO 角色全面退化）；DPO 强化 SFT 已学会的行为、不能注入 SFT 没学会的知识 |
| 叙事要点 | "从 RAG → Prompt → SFT → RLHF，理解整条链路的能力边界和工程权衡，并亲自踩过'DPO 不能脱离 SFT'的坑" |

## 项目五：AI 安全评测（✅ 已完成）

| 维度 | 内容 |
|------|------|
| 覆盖能力 | 全维度综合评测：功能评测 + 安全评测 + 对齐税检测 |
| 目标 | 对自己完整搭建 + 训练的对齐模型做系统评测，验证安全边界 |
| 关键动作 | ① 20 条功能测试（风控/RAG/AI 工程/边界）；② 18 条安全测试（注入/越狱/敏感/多轮诱导/输出安全）；③ 三条实验链纵向对比 |
| 关键结果 | 功能准确率 75%、安全防御率 94.4%、边界拒答 100%、无对齐税、综合 87.6 分 |
| 叙事要点 | "安全方向 PM，不是写理论报告——拿自己完整训练的对齐模型做靶机实测，18 种攻击 94.4% 防御成功" |

## 执行顺序

```
项目一 RAG     ──→ 项目二 查询改写 ──→ 项目三 SFT ──→ 项目四 RLHF/DPO ──→ 项目五 安全评测 ──→ 项目六 作品集
 (✅ 已完成)       (✅ 已完成)        (✅ 已完成)     (✅ 已完成)         (✅ 已完成)       (✅ 已完成)
```

**顺序调整说明**：

- 安全评测放在 SFT 和 RLHF 之后，因为微调和对齐训练会改变模型行为，安全评测应针对最终模型做，否则评测完又改模型，结果失效
- SFT 和 RLHF 强依赖：必须先有 SFT 模型才能做 RLHF/DPO，不能反序
- 每个项目完成后更新交接文档和项目收尾材料，保持接力可续

## 关键约束提醒

| 约束 | 影响 |
|------|------|
| API Token 余额有限 | 测试分批执行，不一次跑完 |
| 知识库存储接近 50MB | 复用现有知识库，不新增文档 |
| SFT/RLHF 需要 GPU | 项目三/四需要算力平台，提前确认可用资源（ModelScope 免费额度 / AutoDL 按量计费） |
| SFT 数据构造耗时 | 项目三最大瓶颈不是训练，是数据质量，提前准备 |
